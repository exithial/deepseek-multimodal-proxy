# Cortex Multimodal Proxy v3.4.0 — Release Notes

## What's new

Cortex Multimodal Proxy v3.4.0 makes the dashboard a real analytical tool, not just a live counter. The hero totals, the chart, and the per-model table all respond to a single time-window selector at the top of the page — pick **24 hours, 7 days, 30 days, 90 days, total, or a custom range**, and every number on the page re-aggregates to match. A new endpoint lets you pull the same data programmatically so you can build your own reports.

For direct-DeepSeek users, this release also restores the maximum-reasoning setting that the previous refactor had accidentally dropped. DeepSeek V4 Pro and Flash now reason at full effort, which is what DeepSeek recommends for agent scenarios and what Flash 0731 was retrained for.

## Dashboard: pick a window, see the numbers that matter

Until now, the hero cards showed totals since the database was first created. As time passed, those numbers grew into the tens of millions and stopped being useful — you could not tell whether you were looking at the last day, the last quarter, or everything since launch. v3.4.0 fixes that.

- **Global range selector** at the top of the dashboard: `24H / 7D / 30D / 90D / TOTAL / CUSTOM`. One click changes every panel on the page — hero cards, chart, and per-model table all read from the same active window.
- **Compact number formatting**: `$48.8 M`, `12.3 K`, `1.23 B` — totals are abbreviated so the cards never overflow, on any locale or any time range.
- **Custom range**: pick a `FROM` and a `TO` date and the page pulls the data for that exact window. Useful for end-of-month reporting, post-incident review, or vendor comparison.
- **The chart obeys the global selector** too. No more toggling two separate controls in two different places.

## Programmatic access for your own reports

A new endpoint, `GET /v1/dashboard/range?from=<iso>&to=<iso>`, returns the same data the dashboard renders, in JSON, for any time window you specify. The series auto-buckets to hourly for spans of 48 hours or less, and daily for longer spans. Requests beyond the configured retention window return a structured 400 with the maximum allowed range in the body.

Use it from your own scripts to:

- Pull last month's token spend per model into a spreadsheet.
- Build a Slack digest that compares this week to last week.
- Wire it into a Grafana panel or a Datadog custom metric.
- Export usage data to your finance team's monthly close.

The data is exactly what the dashboard sees, with the same cache-hit attribution, the same cost per million tokens, and the same per-model and per-brain breakdown.

## Direct DeepSeek: max reasoning, restored

If you run the proxy against your own DeepSeek account (`BRAIN_MODE=deepseek` or `hybrid`), the proxy now sends `reasoning_effort: "max"` on every direct DeepSeek call — both Pro and Flash. The previous release had silently dropped this setting during a refactor, so direct DeepSeek was reasoning at `high` instead of `max`. The fix is a one-line change in the payload builder; the impact is on the quality of every response DeepSeek produces for you.

This change only affects the direct-DeepSeek path. The OpenCode Go flavor (the alternative way the same models reach the proxy) is unchanged — it always inherited the upstream default.

## What's stable

- The proxy's public API (`/v1/chat/completions`, `/v1/messages`, `/v1/models`, `/health`, `/v1/cache/stats`) is unchanged.
- BRAIN_MODE behavior, model selection, multimodal pipeline, and retry policy are unchanged.
- The existing `/v1/dashboard/snapshot` endpoint still works. The new `/v1/dashboard/range` is purely additive.
- Existing clients do not need to change.

## Upgrading

1. Pull the new image or checkout the v3.4.0 tag.
2. Restart the container. The new dashboard range selector appears automatically; no env changes required.
3. If you want to use the new endpoint programmatically, hit `GET /v1/dashboard/range?from=<iso>&to=<iso>` from any tool that can call the proxy. Keep the range inside `DASHBOARD_RETENTION_DAYS` (default 90) or you will get a 400 with the maximum allowed span in the body.
4. If you operate in `BRAIN_MODE=deepseek` or `hybrid`, the `reasoning_effort: max` change is automatic — no configuration needed. Expect higher-quality (and slightly slower) responses from DeepSeek V4 Pro and Flash.
